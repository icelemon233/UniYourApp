# README 编写方法

面向正在判断是否采用项目、并准备第一次使用的人写作。安排章节前，先确定真实读者、可用入口和预期结果。README 是面向使用者的入口；完整代理规则、个人配置和维护记录各有自己的文件。

## 先核实事实

阅读现有 README、项目约定、包元数据、真实安装路径和代表性用户流程。按实现核对兼容性与必要条件，保留产品真实名称、范围和语言选择，不从开发者机器推断公开身份或配置。

用户要求对比研究时，选择真正可比的项目：单个技能、技能集合、工作流框架和目录索引的读者不同。用当前一手元数据核对筛选条件，再读取默认分支的实际 README。用户偏好个人项目时优先个人账号，但不据此断言没有团队或贡献者。星标只是筛选条件，不证明某种写法带来了采用量。普通修改不强制研究固定数量或固定星标门槛的项目。

## 缩短首次使用路径

- 开头使用真实项目名，直接说明能帮助读者完成什么。只有会影响采用决定的区别才值得补充，不叠加口号、副标题和含义相同的介绍段。
- 尽早提供完整的首次使用路径：必要环境、一种首选安装或访问方式、一个真实可用的请求或命令，以及读者能辨认的结果。只有安装命令还不足以说明技能怎么用。
- 按读者基础决定解释深度。面向初次接触技能的人，说明技能与 Agent 的关系、准备条件和识别成功的方式，手动步骤与进阶操作可按需展开。通用技能的主路径使用工具无关的表述，具体导入位置遵循所用 Agent 的说明。
- 平台差异只在改变设置方式时展开。简短差异可用表格或折叠内容，复杂设置放进链接指南。不编造通用安装命令，也不宣称未经核对的宿主兼容性。
- 结构随项目规模决定。单一技能可以只有简介、安装、例子和少量链接；集合适合任务与能力对照表，完整工作流才需要简短流程。不把完整目录、全部功能或整个生命周期套到每个 README。

## 让能力具体可见

展示读者能识别的任务，以及帮助完成它的实际行为。优先使用短请求、真实前后对照或真实截图，少写宽泛的质量和效率承诺。示意输入明确作为例子，不伪造输出、性能成绩、背书、使用量或截图。

视觉工具有合适真实结果时可以展示，并保留来源与可读尺寸。文字工作流可以用简短请求和预期行为说明，不必添加装饰性首图。同一功能不要在介绍、列表、表格和结尾各说一遍。

用户选择品牌首图时，围绕项目名称与含义组织视觉元素，核对名称拼写和缩小后的可读性。功能与效果的描述以项目的实际能力和证据为依据。案例、截图和具体工程规则按首页的说明需要取舍。

## 区分通用产品与可选配置

默认路径面向目标通用读者。项目品牌、个人目录、私人素材、本地模型默认值和需选择启用的配置，不占据首页介绍与安装主线。细节写入相应配置文档，只在帮助读者选择或配置功能的位置链接。

实现路由和完整行为规则放在 `SKILL.md` 与参考文件；开发检查、架构内部细节、变更记录、对比研究和贡献流程放到合适的补充文档。真实要求写在受影响功能附近，例如某种验收模式需要真实浏览器或两个独立模型。

## 克制使用结构

每个标题、标签、徽章、表格列、图注和说明句都应提供有用信息。标题直接描述内容，段落保持连贯，并列事项才用列表。表格用于帮助选择任务或平台，不用于将普通段落包装成卡片。

保留必要条件、失败行为、许可证和兼容限制，不增加假想风险或防御性章节。状态徽章需要有意义的真实来源。热门项目中的赞助、个人经历、星标曲线和推广内容，不因此成为另一个项目的必备项。

## 本地化与验证

- 首页语言与双语形式按用户要求或项目读者确定。独立语言文件之间提供清楚的双向入口。采用同页对照时，每段中文紧接对应英文，标题合并为双语，共用命令与图片可只出现一次。每种语言都完整说明用途、安装、使用与重要条件。
- 自然翻译，保持标识符、路径、命令、约束、功能和承诺强度一致。双语技能包只启用其中一版，并确认两版都不依赖另一个版本的文件。
- 安装路径改变时，在安全临时位置验证真实流程。检查 GitHub 实际渲染中的代码块、表格、相对链接、图片和折叠内容，确认默认展示哪个 README。
- 连续通读开头、标题和结尾，删除重复解释与维护过程叙述。确认首次有用操作容易找到，描述仍与真实仓库相符。
